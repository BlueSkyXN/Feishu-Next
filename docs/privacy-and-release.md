# 隐私检查与干净发布包

本规则防止误提交和误打包，不代表自动扫描能证明所有内容都适合公开。它不读取用户真实认证存储、不调用飞书 API、不上传源码、不更新工具、不撤销授权，也不重写 Git 历史。

## 1. 私人资料留在本地

根 `.gitignore` 明确排除 `/local/`，不依赖某台电脑的全局 Git 忽略规则。既有 diagrams、导出、聊天归档、缓存和压缩包忽略规则继续保留。

不要为了通过校验删除本地研究记录或导出物。忽略规则不能撤回已经跟踪的文件；隐私检查会独立拦截被强制加入 Git 的私有目录和生成物。手工 ZIP 整个工作目录不遵守 `.gitignore`，因此禁止把整个仓库目录或未经筛选的插件目录直接压缩发布。

## 2. 本地检查入口

```bash
make validate-privacy
make validate-privacy-history
```

等价于：

```bash
python3 scripts/validate_privacy.py
python3 scripts/validate_privacy.py --history
```

默认检查：

- 当前已跟踪文件和依据仓库 `.gitignore` 得到的未跟踪候选文件；个人全局忽略或 `.git/info/exclude` 不能隐藏候选。
- Git 暂存区的独立内容，避免工作区已经脱敏、暂存区仍保留原文。
- 凭据字面量、JWT、私钥、私人绝对路径、飞书身份/资源 ID、租户资源 URL、邮箱和手机号。
- 私有目录、导出目录、缓存、旧压缩包、认证文件及符号链接误入提交。
- 使用已安装的 Gitleaks 默认规则进一步识别常见秘密与编码内容；临时扫描副本在系统临时目录，结束后清理，不留下原文报告。

`--history` 增加所有本地可达提交中的文件版本，以及 Gitleaks Git 历史检查；不联网 fetch，不代表覆盖服务器上未拉取的分支、发布附件、聊天或 CI 日志。

输出只含范围、文件位置、行号、规则及命中值 SHA-256，不输出原文、token 或匹配上下文。路径本身也可能敏感，完整诊断结果仍应在分享前复核。退出码：0 为检查通过，1 为发现问题，2 为检查没有完整运行。

### 依赖与降级

需要 Python 3.10+、Git 和已安装的 Gitleaks 8.30+。脚本不自动安装依赖；缺 Gitleaks 时默认失败，不假装完整扫描通过。

仅做非发布静态检查时可显式运行：

```bash
python3 scripts/validate_privacy.py --static-only
```

它仍执行路径/内容和暂存区检查，但明确跳过 Gitleaks，不能用于发布门禁。`make validate` 先运行完整隐私检查，再运行既有项目校验和单元测试；缺少 Codex plugin validator 仍是另一个独立失败，不被隐私通过掩盖。

## 3. 误报与精确例外

`scripts/privacy_allowlist.json` 只接受**具体文件路径、具体规则、具体命中值哈希、解释原因**。不支持通配符、整目录免检或自动学习基线。

现有例外仅用于已人工核对的 TraeWork 公共 client ID 和合成 MCP 测试值。它们不是个人身份或生产凭据。相同文件里的不同值，或者复制到其他文件的相同值，仍会报错。检查器自身和全部测试文件也照常扫描。

新增例外须先确认为什么该值可以公开，不能把真实秘密的哈希放进白名单来消除告警。Gitleaks 命中不受此规则白名单影响；不加载用户提供的扫描器配置、忽略文件或行内放行注释。

## 4. 发布包来自审核后的提交清单

只在用户另外授权发布时，按以下过程准备包：

1. 审核目标源码并完成必要提交，由维护者选择精确本地 commit/tag；不能把“当前目录内容”当发布清单。
2. 从该 revision 枚举 `plugins/<plugin>/` 的 Git 文件与仓库 `LICENSE`，只复制这些条目的已提交 blob 到全新的临时目录。目录布局为 `<plugin>/.codex-plugin/...`、`<plugin>/skills/...`、`<plugin>/README.md`、`<plugin>/LICENSE`。
3. 许可及其他必要资源必须已经纳入该 revision。不要把仓库外部绝对路径、软链接目标、忽略文件或旧 ZIP 加入暂存目录。
4. 生成 `<plugin>-<version>.zip` 到已忽略的 `dist/`；如果目标包已存在先查看，不擅自覆盖。
5. 对最终 ZIP 而非仅对源码运行下面的只读检查，然后人工复核文本与可见内容。任何失败都阻断上传，不自动删除原件或改写历史。

```bash
python3 scripts/validate_privacy.py --history \
  --archive dist/feishu-next-0.7.0.zip \
  --plugin feishu-next \
  --ref '<reviewed-commit-or-tag>'
```

这里是示例文件名，实际版本来自该提交中的 manifest。本命令只检查已有 ZIP，不创建包、不提交、不发布。

ZIP 检查会逐文件比对所选提交的清单和字节，包括许可证；多余、缺少、被改过的文件都失败。它还拒绝路径穿越、绝对路径、重复/大小写冲突路径、符号链接、加密条目、嵌套压缩包、`.DS_Store`、`__MACOSX`、`__pycache__` 等杂项。ZIP 全局/条目注释及额外元数据字段也被拒绝，避免通过文件内容以外的字段夹带信息；生成包时不要写入这些字段。不会把压缩内容解压到仓库。

当前默认单文件上限 8 MiB、包内逻辑总大小 50 MiB、最多 5,000 项，超限直接失败。二进制或非 UTF-8 文件会要求单独隐私审查，不因无法扫描而放行；需要发布真实图片/附件时先增加有证据的审查机制，不能仅扩大上限绕过检查。

当前本地已有的旧 ZIP 不是合格的发布输入，不自动清理或覆盖它。正式发布应重新从审核清单生成干净包。

## 5. 不要把运行输出误当公开日志

TraeWork 鉴权工具的 `status` 可能含本机路径，`fetch-uat`/`whoami` 可能含人员或组织信息；不打印完整令牌不等于没有隐私。`export-env` 的用途就是输出真实短时令牌，仅在用户明确要求时运行，其结果不可进入公开日志或源码。

隐私扫描不主动执行这些命令，不用真实凭据验证疑似秘密是否有效。收到告警时先保留证据并阻断发布，确认是否已外泄后再由用户决定轮换、撤回或历史清理。

## 6. 验收与局限

回归测试使用临时合成 Git 仓库和 ZIP，覆盖工作区/暂存区不同步、被全局忽略的候选、历史删除残留、精确白名单、ZIP 清单差异和不安全条目。它们不向当前仓库 add/commit，不访问业务数据。

扫描不能自动识别所有公司术语、截图内容、财务数据、陌生凭据格式或发布授权。结果是防误操作门禁，不是“已经证明可公开”的承诺。发布前仍需审查内容、许可证、所选 revision 与用户授权。
