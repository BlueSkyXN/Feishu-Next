# 云文档、云空间与知识库能力地图

这份地图用于解释“能做什么、该选谁”，不是 API 手册或权限保证。按 `lark-cli 1.0.97` 的本地官方指南核对；实际执行仍读取当前选中的指南及所需参考。按 [官方导航规则](official-suite-navigation.md) 从实际可用的 suite、独立技能或 runtime reads 加载，不假定 suite 已安装。能力咨询无需提供资源链接、认证或业务访问。

## 云文档正文 — `lark-doc`

**能做什么：**读取全文、目录、章节、区间或关键词命中内容；获取内容供摘要；从零创作、创建空文档、编辑、补写、润色、重组和排版；插入、预览、下载图片附件；处理 Docx 封面；查询及按授权恢复文档历史版本。已有思维笔记的内容和节点也从本指南进入。

**常见表达：**“帮我写一篇飞书方案”“总结这篇文档”“只改第三章”“插入这张图片”“看看之前的版本”“修改思维笔记节点”。

**下一步读什么：**先读 `lark-doc`；读取场景选 fetch 参考，从零创作选创建工作流，已有正文修改选 update，历史版本选 history。具体能力与支持的块类型由当前参考决定，不把“可编辑”解释为所有对象都能任意重建。

**不要混淆：**
- 找文档、创建副本、改标题、移动、导入导出、权限、独立评论属于 `lark-drive`。
- “复制一份”是复制资源，不是读取正文再创建，以免丢失结构和资源。
- 读取正文可以带评论上下文，但添加、回复、解决或完整分页读取评论走 Drive。
- 文档里的内嵌 Sheet、Base、白板需要再读对应领域指南；看到资源 token 不等于读到内部数据。
- Wiki 链接的正文可能是 Docx，也可能是其他资源；先确定底层对象。不要仅凭 `/wiki/` 就使用知识库目录操作。

**何时选 Next：**
- “按参考统一排版”或“把这些章节按规则设成 H2”选 `$feishu-next:feishu-doc-format-align`：应用已知样式规则，默认保留材料划分与正文文字，逐段逐格验证。
- “标题挂错章节”“粘贴后出现星号/CSS”或“多篇材料串在一起”选 `$feishu-next:feishu-doc-format-repair`：诊断结构错位和粘贴损伤，逐项核对获准差异；单份内容也适用。
- 只说“格式乱了”时先诊断症状，再按样式不一致或结构/粘贴损伤选择；只要求“看看”时保持只读。
- 同时要求修复和统一样式时，先验收 repair，再把最新快照、revision、块映射和遗留项交给 align，复用有效上下文。两者分别维护自己的完整编辑与验收规则。
- “盘点全部图片附件和嵌入资源，给清单”选 `$feishu-next:feishu-doc-asset-map`，增加资产分类和可追溯交付。
- “在同一份思维笔记里调整整份大纲，保留节点和备注”选 `$feishu-next:feishu-mindnote-outline`，增加层级映射、差异更新和节点复用。
- 普通读取、创作或修改直接复用官方方法；不能因为文档创作本身有多个步骤就强行包成 Next 工作流。

## 云空间与文件治理 — `lark-drive`

**能做什么：**按名称或条件找文件；识别资源类型和真实 token；上传下载普通文件；导入导出在线文档；创建文件夹、复制、移动、删除、改标题；查看元数据和历史版本；管理评论、协作者、分享权限及密级标签。写入与高风险动作必须满足当前指南的精确授权要求。

**常见表达：**“找我最近编辑的文档”“另存一份到这个目录”“把 Word 导入飞书”“导出 PDF”“看看谁能访问”“回复这条评论”。

**官方已有的多步方法：**权限治理、已知目录的结构整理、按主题跨范围收集资料，先读 `lark-drive` 的 `references/lark-drive-workflow.md`，选择其登记的方法。不要跳过它直接拼搜索和移动命令，也不要在 Next 复制这些流程。按评论定位正文时读取 `references/lark-drive-comment-location.md`，核对当前 `drive +list-comments --need-relation` help。

**边界：**云文档正文修改走 Doc；Sheet/Base 内部数据走各自领域；Wiki 节点层级走 Wiki。把本地文件导入为 Base 是 Drive 的导入步骤，导入后的表内操作才是 Base。已有 Wiki 节点移出知识库走 Wiki，而不是把 Wiki 节点 token 当作普通文件移动。

**何时选 Next：**`$feishu-next:feishu-readonly-doc-export` 用于带源类型、输出文件、任务续查和完成证据的只读导出。普通复制、移动、权限治理不借导出工作流绕行。需要先盘点再导出或交付结果时，Router 组合必要步骤，并保留后续发送/发布的独立边界。

## 知识库结构 — `lark-wiki`

**能做什么：**查看和管理知识空间、成员、节点和层级；组织文档或快捷方式；在授权范围内创建、复制、移动节点及把节点移出知识库。

**常见表达：**“看看知识库目录”“在这一章下面建个文档”“移动到另一个节点”“给空间加成员”。

**边界与 Next：**知识库目录不是文档正文，节点成员不是每种底层对象的所有权限。上传普通文件到 Wiki 节点遵循 Drive，正文修改遵循实际对象指南。没有专属 Next 知识库技能；若任务还涉及归档、导出或保真排版，由 Router 组合现有玩法，不编造新入口。

## 原生 Markdown — `lark-markdown`

**能做什么：**读取、创建、上传、局部编辑和比较飞书云空间中的原生 `.md` 文件，比较历史版本或远端与本地草稿。

**常见表达：**“改这个飞书 Markdown 文件”“看看和本地稿差了哪些内容”。

**边界与 Next：**纯本地 Markdown 不需要飞书能力；把 Markdown 导入成在线 Docx 属于 Drive；文件搜索、权限、评论、移动删除也走 Drive。不要把原生 Markdown 的编辑错误导向 Docx 排版玩法。

## 组合时的判断

“读文档并总结”通常由官方 Doc 方法覆盖。“盘点资源、导出文件、发送给指定群”则由 Next 维护资产盘点、导出、官方 IM 步骤的依赖与验收。选择依据是附加的方法和交付约束，而不是简单按单步/多步划分。任何能力地图中的写操作都只是能力说明，不构成执行授权。
