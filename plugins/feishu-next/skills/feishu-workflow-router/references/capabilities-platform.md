# 认证、事件与扩展能力地图

这份地图只描述入口和边界。通过 [官方导航规则](official-suite-navigation.md) 加载实际可用的官方指南；命令、身份、scope 和风险以当前 CLI 为准。询问“支持什么”不要求登录，不发业务请求，也不授权安装或变更配置。

## 认证与公共规则 — `lark-shared`

- **能做什么：**解释配置/登录状态、user/bot 身份、业务域与 scope、缺少权限、撤销授权、CLI notices 和公共错误处理。
- **触发：**“用哪个身份”“为什么没有权限”“怎么授权”。
- **边界：**缺 scope、资源未分享、执行上下文不匹配是不同问题。Next 的 profile/App/identity 契约不由通用登录建议覆盖；不得通过改默认账号或重登绕过 mismatch。
- **Next 关系：**Router 负责工作流的显式执行上下文，不另写一套 OAuth。可选本地鉴权插件不是默认前置条件，也不能扩大原有权限。

## 事件订阅 — `lark-event`

- **能做什么：**按官方事件键消费 IM、审批、任务、会议等事件流；可以用受限事件数/时限进行有界运行。
- **触发：**“监听群消息”“处理审批状态变化”“接收卡片回调”按领域与 Event 指南协作。
- **边界：**事件监听不等于已创建定时任务、常驻守护进程或部署服务。自动回复、持续运行和后台安装必须是用户请求的一部分，不能从一次读取自动扩展。
- **Next 关系：**只有用户要求时将事件作为工作流输入；不因 Next 有“编排”二字就自动起后台系统。

## 开放平台应用管理 — 当前 domain help

应用 slash commands 等平台自身管理先读 `lark-cli application --help` 及匹配的 shortcut help；当前没有 `lark-application` 技能，不猜造。它不是 BaseApp，也不是妙搭应用开发。无对应嵌入技能的领域可以使用实际 help，不把缺技能当成缺权限。

## 原生 API 探索 — `lark-openapi-explorer`

当官方领域指南、现成工作流、已注册 typed command 和 shortcut 均不能覆盖需求时，再查官方原生 OpenAPI。不能用裸 API 绕过拒绝或发行版策略；原始 HTTP 写方法仍需业务风险分类、精确授权和相应验证。找不到命令不自动意味着该 API 不存在，也不意味着允许直接使用 UI。

## 自定义技能 — `lark-skill-maker`

当用户明确要把反复使用的 CLI 操作沉淀成可复用技能时，使用官方制作指南。执行一次业务任务不自动创建技能，也不直接公开私人字段、脚本或业务数据。

## 更新边界

概览按本地 `lark-cli 1.0.97` 指南核对。版本提示或能力缺口只提供信息；只有用户明确指挥 AI 更新时才改插件、CLI、suite/separate 布局或技能注册。不会通过本地图读取自动更新任何安装。
