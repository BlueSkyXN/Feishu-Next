# 电子表格与多维表格能力地图

这里只帮助选能力，不保存 API 参数或组织字段。概览按本地 `lark-cli 1.0.97` 官方说明核对；使用 [官方导航规则](official-suite-navigation.md) 加载实际可用的指南，并以当前 runtime/help 为执行依据。无需认证即可解释能力，但不能据此宣称目标资源有访问或写入权限。

## 电子表格 — `lark-sheets`

**能做什么：**创建和操作工作簿、工作表、行列与单元格；读写值和公式；合并、尺寸、隐藏、冻结和分组；格式、批注、图片；区域复制移动、排序填充与查找替换；图表、透视表、条件格式、筛选器、下拉列表等；公式校验、历史版本及本地表格文件相关流程按官方参考处理。

**常见表达：**“改这个单元格公式”“统计每月金额并画图”“冻结首行”“把这张在线表整理成报表”“检查公式迁移”。先读 `lark-sheets`，再按单元格、结构、图表等目标读对应参考。

**边界：**
- 按标题搜索一份云空间表格文件先用 `lark-drive`；表格内查找单元格才用 Sheets。
- Base/bitable 不是 Sheets；Docx 正文里的普通表格仍是文档块，不是独立电子表格。
- 文件导入导出遵循当前官方指南指向的 Sheets/Drive 路径，不靠扩展名猜表内 schema。
- “能做图表/公式”不表示每种对象、公式或 Excel 特性都兼容，需核对当前指南和必要的验证资源。

**何时选 Next：**带完成证据的文件导出选 `$feishu-next:feishu-readonly-doc-export`。`feishu-doc-format-align` 只做 Docx/Wiki 正文保真排版，不是电子表格美化入口。没有专属 Next 通用统计或财务建模技能；使用官方 Sheets 方法，需要跨文档/消息交付时再由 Router 衔接。

## 多维表格与 BaseApp — `lark-base`

**能做什么：**管理 Base 数据表、字段、记录、视图、统计、公式/lookup；表单、仪表盘；应用模式 BaseApp/AppMode 页面组件；Workspace 目录、工作流、角色权限和模板中心。先解析请求指向表、视图、表单、Dashboard 还是应用页面，再读相应官方参考。

**常见表达：**“筛选这张表的记录”“新增一个字段”“做个表单”“调整 Base 仪表盘”“设置应用模式页面”。

**边界：**
- BaseApp 属于 Base，不是妙搭 `lark-apps`。
- 把本地 Excel/CSV/`.base` 导入成 Base，先用 `lark-drive`；完成后才用 Base 的字段和记录能力。
- 文档里引用 Base 只提供定位信息；读表内数据需要明确的 Base 目标和权限。
- 请求查询记录不授权创建 schema、删除记录或修改 Dashboard。一般模糊查询先采用有界读取，不默认全库扫描。

**何时选 Next：**周月冻结快照、跨周比较、补缺口及部分失败续做选 `$feishu-next:feishu-base-snapshot-maintain`。它增加业务键、幂等、差异计划和历史保护，不内置公司字段，不负责修改 schema、Dashboard 或自动化。普通增改一条记录直接使用官方 Base 方法。

## 选择示例

- “把这个表头改成蓝色”：先识别是 Docx 普通表格、Sheet 还是 Base 视图，不因都有“表”就选择同一路径。
- “看看本周快照缺了什么，先别写”：Next 快照只读检查，官方 Base 提供实际数据读取；检查不授权补写。
- “把 CSV 导入 Base 并检查字段”：官方 Drive 导入与 Base 验证即可，不自动创建快照或公司业务模型。
